## Код‑стайл/линтеры

1. Не используется typing. Типизация - только встроенная.
2. Никаких пустых dict/tuple/list для сложных структур: если структура не тривиальная - описываем в structures.py (DTO/контракты) или constants.py.
3. Для каждого блока кода писать короткий комментарий, что делает код, без точки в конце.
4. Функции должны быть написаны с типизацией параметров на вход и на выход.
5. Docstring формат везде одинаковый:
    - Для функций:

```python
Короткое описание, что делает функция.

Parameters:
    название (тип): Описание. По умолчанию: значение.
    название (тип): Описание.

Returns:
    тип: Описание.

Fallbacks:
    Описание.
```

    - Для классов:

```python
Короткое описание класса.

Attributes:
    название (тип): Описание. По умолчанию: значение.
    название (тип): Описание.

Fallbacks:
    Описание.
```

## Кодировка и редактирование файлов на Windows

- При работе на Windows запрещено изменять текстовые файлы через shell redirection и shell-generated output.

- Запрещены способы записи, зависящие от кодировки терминала/консоли:
    - `echo ... > file`
    - `echo ... >> file`
    - `printf ...`
    - heredoc / here-string с записью в файл
    - `Out-File`
    - `Set-Content`
    - любая другая запись файла через shell, зависящая от encoding консоли

- Текстовые файлы, особенно с кириллицей, разрешено изменять только:
    - через patch/editor tool
    - или через Python c явным `encoding="utf-8"`

- Безопасный паттерн записи:

```python
from pathlib import Path

path = Path("file.md")
text = path.read_text(encoding="utf-8")
text = text.replace("старое", "новое")
path.write_text(text, encoding="utf-8", newline="\n")
```

## Security‑предостережения

1. Не устанавливай сам пакеты, проси их установить у меня.
2. Читать и изменять файлы можно только в рамках папки где лежит этот файл и в подпапках от него.
3. Не запускай тесты, если нужен их вывод попроси у меня.
